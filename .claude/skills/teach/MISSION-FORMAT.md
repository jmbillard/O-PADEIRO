# Formato do MISSION.md

O `MISSION.md` fica na raiz do espaço de ensino. Ele registra o _motivo_ pelo qual o usuário está aprendendo o assunto. Toda decisão de ensino (o que ensinar em seguida, que fontes trazer, que exercícios criar) deve remeter a este documento.

## Modelo

```md
# Mission: {Topic}

## Why
{1-3 sentences. The concrete real-world goal the user is chasing. What changes in their life or work when they have this skill? Avoid abstract framings like "to understand X"; push for the underlying outcome.}

## Success looks like
- {A specific, observable thing the user will be able to do}
- {Another specific thing}
- {…}

## Constraints
- {Time, budget, prior commitments, learning preferences, anything that bounds the approach}

## Out of scope
- {Adjacent topics the user explicitly does not want to chase right now, protecting the zone of proximal development}
```

## Regras

- **Uma missão por espaço de ensino.** Se o usuário quer aprender duas coisas sem relação entre si, são dois espaços.
- **Concreto em vez de abstrato.** "Correr uma meia maratona até outubro" é melhor que "ficar em forma". "Entregar uma CLI em Rust para o meu time" é melhor que "aprender Rust".
- **Não aceite o vago.** Se o usuário não consegue dizer o porquê, entreviste-o antes de escrever qualquer coisa. Uma missão ruim é pior que nenhuma missão.
- **Revise quando a realidade mudar.** Missões mudam. Quando o objetivo do usuário mudar, atualize este arquivo: não deixe uma missão desatualizada orientando as próximas sessões.
- **Seja breve.** Se o `MISSION.md` passa de uma tela, deixou de ser uma bússola e virou um plano.
